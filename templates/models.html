PREPROCESSING SAFEGUARD

Data Leakage Prevention

StandardScaler is fitted only on the training data to prevent information from the test set from influencing preprocessing. The scaler learns its parameters from the training data only. The same fitted scaler is then applied to the test data.

Training continuous-feature mean {{ '%.6f'|format(leakage['train_max_abs_mean']) if leakage['available'] else '—' }} Scaler fitted on these {{ '{:,}'.format(leakage['train_rows']) if leakage['available'] else '' }} rows
Testing continuous-feature mean {{ '%.6f'|format(leakage['test_max_abs_mean']) if leakage['available'] else '—' }} Transformed only — never used to fit
Scaled continuous features {{ leakage['continuous_count'] if leakage['available'] else '—' }} cont1 – cont14 standardised

Both values are the largest absolute mean across the {{ leakage['continuous_count'] if leakage['available'] else '14' }} scaled continuous features, exactly as verified in 02_ClaimWise_Data_Preprocessing.ipynb. The training value is 0.000000 because the scaler was fitted on those rows, while the test value is not zero because those rows only inherit the transformation. The important point is that StandardScaler is fitted only on the training data — the two means are not equal because of how they were produced, not as a standalone proof that leakage is impossible.
